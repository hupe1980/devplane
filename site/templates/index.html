The loop

  1. SpecifyThe spec you already write: Spec Kit, OpenSpec, Kiro or plain Markdown.
  2. Start a changeIts own worktree and branch, an agent, the tasks you chose.
  3. SuperviseQuestions, permissions and red checks across every project, most urgent first.
  4. VerifyYour own check passed against the tree exactly as it stands, or it is not verified.
  5. Review and offerWeakened checks first, then a draft pull request of exactly the tree that passed.

What makes it different

Weakened checks first

A skipped test, a deleted assertion, an edited CI file or lockfile leads the review, and the offer waits until you have read it.

Verified done

Base checks

The base branch's tests run on the change, and the change's new tests on the base: in CI with devplane verify.

A certificate anyone can re-run
